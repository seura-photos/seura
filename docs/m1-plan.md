# M1 work plan: walking skeleton

Status: ready to start · Last updated: 2026-10-18

The working plan for milestone M1 from the [milestone plan](milestone-plan.md), for Claude Code. It breaks the milestone into slices, one pull request each, in order. The goal is to prove every risky piece on both platforms before features are built on them ([technical design](technical-design.md), section 13). Nothing in M1 needs to look finished; the styled UI comes in M2.

## How to work

- **One slice per branch and pull request**, branched from `main`. Name branches `m1/<slice>`, for example `m1/scaffold`. Nevada merges. `main` is protected; never push to it directly unless Nevada asks.
- **Read first:** `CLAUDE.md`, the product brief, the functional spec, the technical design, and the decision records. Follow them; if something in this plan conflicts with them, they win, and you raise it.
- **Use current, stable versions.** Check crates.io and npm for current releases rather than relying on memory, and prefer versions at least two weeks old. Record any library choice that differs from the technical design in a short note or decision record.
- **Check every dependency's license** before adding it (decision 0012: no GPL; LGPL only dynamically linked). `cargo-deny` enforces this from slice 1.
- **Ask Nevada** whenever a step needs his machines (running the app, checking an image by eye, testing Windows), his photos, or a decision the documents don't settle. He tests on one up-to-date MacBook Pro and one up-to-date Windows desktop.
- **Never commit personal photos.** Test images in the repository must be ones the project may redistribute (generated, or explicitly public-domain or CC0). Nevada's own test library lives in `test-libraries/`, which is git-ignored.
- **Journal as you go:** add short notes to `docs/journal/` for decisions, surprises, and mistakes (see its README).

## Slices

### 1. Scaffold and CI

- Cargo workspace and Tauri 2 app as laid out in the technical design, section 2: `src-tauri/`, the four crates (empty but compiling), `ui/` (React, TypeScript, Vite), `tests/`.
- `third_party/edit-format` as a git submodule of `seura-photos/edit-format`.
- Typed bindings between Rust commands and TypeScript (tauri-specta, or the current equivalent).
- Formatting and linting: `rustfmt`, `clippy` (warnings as errors), ESLint and Prettier for the UI. `cargo-deny` for licenses and advisories.
- GitHub Actions: build, lint, and test on `windows-latest` and `macos-latest`, plus an older macOS image for the WebGL2 path once it exists (slice 5).
- App icon generated from `design/brand/app-icon.svg` and `app-icon-small.svg`.
- Update `CLAUDE.md`: replace the Status section with real build, test, and lint commands.
- **Done when:** `cargo tauri dev` opens an empty window on Nevada's Mac and Windows PC, and CI passes on both platforms.

### 2. Edit files and the data-safety suite

- `seura-edit`: parse, validate against `third_party/edit-format/schema/1.0.json`, canonical order, preserve unknown operations and fields exactly, history records, and atomic writes (temporary file in the same folder, then rename).
- Tests run every file in the format's `examples/` (must load and round-trip byte-for-byte equivalent JSON) and `tests/invalid/` (must be rejected).
- Start `tests/data_safety/`, enforcing the rules in `CLAUDE.md`: originals are never opened for writing, nothing is written outside the allowed locations, an unparseable edit file is never overwritten, unknown content survives a save. Use a temporary directory and check file hashes and directory listings before and after.
- **Done when:** both test sets pass in CI on both platforms.

### 3. Library scan, index, and benchmarks

- `seura-library`: add a folder, scan it recursively (LIB-1, LIB-7, LIB-8), fingerprint files, build the in-memory index, and write and load the index snapshot in the cache folder.
- Benchmarks (decision 0010): generate a synthetic library of 100,000 entries and measure snapshot load time, memory use, and filter and search times against the targets in the functional spec (PRF-1 to PRF-7, FND-3).
- **Done when:** the benchmarks run in CI and the results are recorded. If the in-memory index misses a target, stop and raise it with Nevada before switching to SQLite; the switch needs a new decision record.

### 4. Decoding and thumbnails

- `seura-image`: decode JPEG, PNG, and HEIC with orientation applied and embedded color profiles converted to the working space (BRW-7). HEIC follows decision 0011: ImageIO on macOS, WIC on Windows when Microsoft's extensions are installed, libheif with libde265 (dynamically linked) otherwise.
- Thumbnails as WebP in the sharded cache, generated by the worker pool with visible items first (LIB-3, DSP-4), served to the UI through the read-only `seura://` protocol.
- A plain, virtualized grid of the scanned folder in the UI.
- **Done when:** Nevada opens a folder of his own photos, including iPhone HEIC files, on both machines, and they appear the right way up with correct color, including on a Windows PC without Microsoft's extensions (the libheif path).

### 5. One edit, end to end

- `seura-render`: the exposure operation as a WGSL shader, the single implementation used by both preview and export (decision 0004).
- Preview in the UI on WebGPU, with the WebGL2 fallback using GLSL translated from the same WGSL by naga. A developer switch (environment variable or debug setting) forces the WebGL2 path on machines that have WebGPU.
- An exposure slider in a minimal editor view; changes autosave to the edit file within a second (EDT-11) through `seura-edit`.
- Export one photo through wgpu to JPEG in sRGB (EXP-5).
- A reference-image test showing preview and export match within a small tolerance, on both paths.
- **Done when:** Nevada edits and exports a photo on both machines, the WebGL2 path is checked on his Mac with the switch, CI passes the older macOS image, and the edit file passes `third_party/edit-format/tools/check.py`.

### 6. Wrap up

- Confirm every "done when" above, and the milestone plan's M1 exit criteria.
- Record the benchmark results and any decisions in `docs/`.
- Draft devlog part 7 in `seura-photos/seura-photos.github.io`, as a draft, following its `CLAUDE.md`.
