# Drafting the M3 plan

- **Claude Code drafted `docs/m3-plan.md`** from the milestone plan, the functional spec, the UX documents, the technical design, and the edit format, as it did for M2: ten slices, each with its "done when", and eight questions for a design session.
- **Safety first:** M3 is the first milestone that writes edit files from the Library, so every slice that writes adds its write path to the data-safety suite before it merges, and all the Library's writes go through one path in the core.
- **Less to build than the milestone's size suggests:** the edit-file library already handles tags, ratings, history, and unknown content (M1), and the index already filters and searches (M1's benchmark: a search keystroke under 8 ms at 100,000 photos). Most of M3 is the UI and the new write paths.
- **A gap found while planning:** tag matching only lowercases today; TAG-2 asks for NFC normalization and full Unicode case folding. It goes into the tags slice.
- **Carried in:** the Library issues from M2 (#72, #73, #74), Node 26, build 0.2 with the Mac signing fix, and the website's early-build section (#76).
- **The design session's answers folded in** (#79): undo in the Library (BRW-11) became its own slice, after tags and the tag tree, since `seura-edit` already has the edit format's undo and the Library only adds the bookkeeping of which photos each action touched. Mixed selections (TAG-8) and the read-only line (TAG-7) went into the ratings and tags slices, the backup folder into the file-problems slice, and the cloud-deletion measurement to the start of the delete slice. Eleven slices now.
