# The Editor's frame (M4 slice 1a)

- **Built overnight by Claude Code, at Nevada's request** ("start slice 1 and do what you can overnight"). Slice 1 is split in two pull requests, both from `main`: the frame (this one), and the preview's settings block.
- **The Editor now opens over the Library, as the Viewer does,** instead of replacing it. So Done or Esc goes back to the same scroll position, as flow 4 asks. Opened from the Viewer, it goes back to the Viewer on the photo it ended on. Opened from the grid, it selects that photo there.
- **One write path.** M1's Editor kept its own copy of the edit file in memory and saved that. Now each change goes through the Library's path (M3 slice 1), as tags and ratings do. That brings the atomic save, the empty-file rule, the checks for read-only folders and unreadable files, and the index update, so the grid's edited badge appears as soon as the change is saved.
- **A drag is one change.** M1 saved whenever the slider paused for 300 ms, so a slow drag made several history records. The edit format says a drag is one record, made when it ends. The slider now saves on the input's own `change` event, which browsers fire when the pointer is released. A run of key presses still waits 300 ms and is saved as one change.
- **Brightness shows on the −100 to 100 scale,** 25 to a stop, as the design session decided for M4. The file still stores stops.
- **A race found while building:** moving through the filmstrip opens the next photo before the last one closes. Closing by id, and opening photos one after another, keeps a late close or a slow open from replacing the photo now shown.
- **A slip caught while inspecting:** the first inspection script found the Seura window by its title. Nevada's installed copy of Seura was also running, minimized, so the script captured that window and resized it. No clicks or keys reached it. Claude Code minimized it again and changed the scripts to find the development build by its path.
- **The second slip:** clicks and keys sent with Windows' input functions go to whichever window is in front. Windows wouldn't bring the Seura window forward while nobody was at the computer, so a click and an arrow key went to another window, harmlessly. The inspection then used only accessibility actions (invoke, select, set value), which reach the window wherever it is.
- **Two filmstrip bugs found by Nevada** in his check by eye, fixed the same morning:
  - The filmstrip flickered as the photo's thumbnail updated after a change. Each new thumbnail made a new image element, empty until it loaded. The grid has always changed the image in place, so the old picture shows until the new one is ready, and the filmstrip now does the same.
  - After a click, the arrow keys left the clicked cell outlined as well as the current one: the outline was the clicked cell's keyboard focus. Focus now moves with the current photo.
- **A third slip:** while fixing these, a shell command written by Claude Code began with a stray `cat >`, which waited for input and left an empty `fs_fix.py` one folder above the repository. Claude Code deleted it and said so.
- **Checked by Nevada on Windows:** light mode, edits kept after a restart, and a cloud-only OneDrive photo, downloaded on opening, with its edit file saved beside it.
