# Zoom in the Viewer (M2 slice 7b)

- **One sharp part instead of a grid of tiles.** The technical design says zooming past the screen's resolution fetches tiles of the full-size photo. Claude did the simplest version of that: the photo decoded to fit the window is enlarged underneath, and once zooming or panning rests, the core cuts the part on screen (plus a quarter of the screen's size around it) from the full-size photo and the Viewer draws it sharp on top. Small pans show sharp pixels at once; big ones show the enlarged photo for a moment. A real grid of tiles can come later if this feels slow.
- **The full-size photo is decoded only when you zoom**, and kept while that photo is shown, so each pan is just a cut. The Viewer now also decodes every photo through the same full-size step, so it always knows the photo's real size, even before its thumbnail has been made.
- **100% means one photo pixel per screen pixel**, as in other photo apps, so on a high-density screen 100% looks smaller than on an ordinary one.
- **A bug avoided by React's own tools:** the first version re-attached the wheel and pinch listeners on every zoom, which would have reset a Mac trackpad pinch's starting point mid-gesture and made it run away. Switching to React's `useEffectEvent`, prompted by its lint rules, attaches them once.
- **The build caught what the tests didn't:** a test passed under Vitest but failed TypeScript's stricter build. CLAUDE.md's checks run both, so it didn't reach CI.
- **On the Mac, nothing zoomed at first,** and opening a photo sometimes failed with "canvas is not configured". Development builds mount the Viewer twice (React's StrictMode), and both renderers share each canvas's one WebGPU context. In WebKit the first renderer's teardown could land after the second had set the canvas up, switching it off. Windows happened to run them in the safe order. A new renderer now waits for the last one on its canvas to go. Nevada then zoomed on the Mac with the buttons, the keys, two-finger scrolling, and pinching. M1's Editor has the same pattern and is left for its rewrite in M4.
