# 2026-10-18: Scaffold and CI (M1 slice 1)

Claude Code scaffolded the workspace on Nevada's Windows PC, on branch `m1/scaffold`.

## Setup

- Claude checked the toolchain before starting: everything was in place except Rust, which Nevada installed with rustup (1.99.1). Claude installed `cargo-deny` and `tauri-cli`.
- Nevada's Node is 24.13. jsdom 30 needs 24.15, so Claude used jsdom 29.1.1 (a test-only package) rather than ask for a Node upgrade.

## Versions

- Rule from the M1 plan: use versions at least two weeks old. Two weeks before today is 2026-10-04, so tauri 2.12.1 (not 2.12.4) and tauri-build 2.7.1.
- Tauri 3 is in alpha. Stayed on Tauri 2, as the technical design says.
- **tauri-specta has no stable release for Tauri 2**: 2.0.0-rc.25 (May 2026) is the latest, and its own docs say to pin it exactly. Claude used it anyway, since typed bindings are a design requirement (decision 0008) and nothing stable does the same job. Pinned with `=`.
- **TypeScript 6.0.3, not 7.** TypeScript 7 (the native Go port) is out, but typescript-eslint supports only `<6.1`.

## Surprises

- **Rust tests on Windows wouldn't start** (`STATUS_ENTRYPOINT_NOT_FOUND`). tauri-build embeds the Windows manifest, which requests Common Controls v6, into the app binary only, not into test binaries. Claude switched `build.rs` to embed the manifest through the linker, so every binary gets it.
- **cargo-deny flagged MPL-2.0** in five crates Tauri depends on (cssparser, cssparser-macros, selectors, dtoa-short via tauri-utils; option-ext via dirs). Decision 0012 doesn't mention MPL. It's file-level copyleft and compatible with an Apache-2.0 app when the crates are unmodified, so Claude allowed it in `deny.toml` and raised it with Nevada to confirm (possibly as an addition to decision 0012).
- **cargo-deny flagged `paste` as unmaintained** (RUSTSEC-2024-0436), a compile-time macro used by Tauri and specta. Not a vulnerability; ignored with a reason in `deny.toml`.
- **The web view writes to a hidden app-data folder.** One `cargo tauri dev` run left 79 MB in `%LOCALAPPDATA%\app.seuraphotos.desktop\EBWebView`. This conflicts with CLAUDE.md rule 2 and decision 0005. Windows lets the folder be moved (`data_directory`); macOS's WKWebView doesn't (only `dataStoreIdentifier`). Claude raised it before starting and left it open for Nevada to decide; it needs a decision either way.
- The edit-format repository has no release tags yet, so the submodule is pinned to its current `main` commit (`0826791`, "Add Seura Edit Format 1.0 draft") rather than a release.

## Choices made along the way

- App identifier `app.seuraphotos.desktop` (Claude's suggestion, from the domain; still open for Nevada to change before the first release).
- `tests/` is a small unpublished crate, `seura-tests`; each suite will be a `[[test]]` target (`data_safety` in slice 2).
- Bindings are checked by a Rust test that fails when `ui/src/bindings.ts` is stale; `npm run bindings` regenerates it. The app itself never writes them.
- App icons: `cargo tauri icon` takes one source, but the design has two (small for 32 px and below). `ui/scripts/icons.mjs` renders both and packs the `.ico` and `.icns` itself, with no extra dependencies.
- The app's only command so far is `app_version`, which proves the whole path: the capability grants only `allow-app-version`, the CSP allows only IPC, and the typed binding is called from React. Screenshot check on Windows: the window showed "Version 0.0.0" in dark mode with the small icon in the title bar.
