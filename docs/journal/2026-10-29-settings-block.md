# The preview's settings block (M4 slice 1b)

- **What changed:** the shaders' uniform block grew from M1's exposure alone to every core operation's parameters except red-eye's regions. That's orientation and flips, straighten, the crop rectangle, exposure, white balance, highlights, shadows, contrast, saturation, black and white, sepia, and the vignette. Each later slice in M4 now adds one shader function, and the parameters are already there to reach it. Red-eye's regions are a list of any length, so slice 7 gives them a buffer of their own.
- **No separate on/off flags,** a small departure from the technical design's wording ("compiled out by uniform flags"). The shader skips an operation whose parameters are neutral, testing the values themselves. A branch on a uniform costs the same as a branch on a flag, and there are no flags to keep in step with the values. Claude Code's choice, said in the pull request.
- **The block's layout has one source, the WGSL.** Three places write the block: Rust for export, and TypeScript for WebGPU and WebGL2. Before, each was written by hand to match: 16 bytes, exposure at 0. Now naga reads the WGSL when the preview's shaders are generated, and writes each field's place to `params.json`, which the preview uses to fill the block. A Rust test checks its own struct against naga's reading, and a UI test checks that every field has a setting.
- **The render check passed** on WebGPU and WebGL2 on Windows, with no difference from export.
- **Rebased onto the Editor's frame (#151)** once Nevada merged it. The new Editor now keeps the photo's saved settings and changes only brightness in them, so the slider can't reset another operation's settings. Hold to compare draws neutral settings. Those come from seura-render's `Settings::NEUTRAL`, exported into the UI's bindings as `NEUTRAL_SETTINGS`, so the preview has no copy of its own to keep in step.
