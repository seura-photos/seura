# 2026-10-18: Edit files and the data-safety suite (M1 slice 2)

Claude built `seura-edit` and started `tests/data_safety/`, on branch `m1/edit-files`. Nevada asked for the slice; the design choices below are Claude's, raised in the PR.

## How it works

- **Keep the file, edit in place.** Each edit file is kept as the JSON exactly as read, with a typed view of the parts Seura understands (technical design §7). An edit changes only the entry it's about, so unknown operations, fields, extensions, and even the order of keys survive a save. `serde_json`'s `preserve_order` feature keeps key order.
- **Validation** uses the format repository's own `schema/1.0.json` from the submodule, plus the three rules JSON Schema can't express, mirroring `tools/check.py`. The `jsonschema` crate is used without its default features, which would include fetching schemas over HTTP (CLAUDE.md rule 6).
- **Saving** writes a visible temporary file in the same folder, flushes it, and renames it over the old one. Before writing, it re-reads the file on disk: if that file can't be parsed, or changed since it was loaded (another computer, another app), the save is refused and nothing is touched.
- **Never downgrade.** A core operation stored in a version Seura doesn't support (say `seura.exposure` version 2) is kept and skipped, and Seura refuses to edit it rather than replace it with version 1.

## Tests, and checking they can fail

- All three examples from the format repository load, round-trip to identical JSON (same keys, order, and values), and are byte-stable when rewritten. All 16 invalid cases are rejected by a rule, not a syntax error.
- The data-safety suite runs a user session over a temporary library of stand-in photos (generated bytes; no real photos). Photos are made read-only, so opening one for writing would fail, and every file's hash, size, modification time, and read-only flag is compared before and after.
- Following the lesson from slice 1 ("test a check by making it fail"), Claude broke the code three ways on purpose: removing the never-overwrite check, dropping plugin operations when editing, and changing a photo's bytes mid-session. Each was caught by the intended tests. Cargo stops at the first failing test program, which at first hid that the data-safety suite also catches the second; rerunning it alone confirmed it.
- A mistake caught by a test: Claude's own expected timestamp in a history test was wrong by a day; the code was right, confirmed independently with Python.

## Open questions for Nevada

1. **Reading newer minor versions.** The spec says a 1.0 reader must still read a 1.1 file and keep what it doesn't know, but the schema accepts only `"1.0"` and rejects unknown fields. Claude's choice: validate 1.1-and-later files with a relaxed copy of the 1.0 schema (unknown fields and new core operations allowed, everything 1.0 defines still checked). The format repository should say how readers validate newer minor versions.
2. **Redo across restarts.** EDT-9 says undo and redo work across sessions, but the history stores only completed actions, with no place for undone ones. Undo survives a restart; redo is kept for the session only. Changing that needs a format change.
3. **Deleting an empty edit file** (FIL-1, the spec's SHOULD) is left for M3. Rule 5 says deletion always goes to the Trash; it should be decided whether that applies to Seura's own edit files too.

## Smaller choices

- A byte-order mark is skipped when reading (some editors add one) and never written.
- Tags are cleaned as the spec requires: leading and trailing spaces and slashes and empty levels removed; of two tags differing only in case, the first is kept.
- Numbers Seura writes are rounded to four decimals, and whole numbers are written without a decimal point (`35`, not `35.0`), matching the examples.
- `seura-edit` reads the schema straight from the submodule. Publishing the crate on its own later will need a vendored copy.
- New dependencies are at least two weeks old, which needed pinning: `jsonschema` and its helper crates to 0.58.5, `sha2` to 0.11.0.
