# 2026-11-06: Google Drive's streamed files on Windows

- **Nevada installed Google Drive for desktop on Windows** and tried the installed 0.4 with it. Drive "streams" files: they're cloud-only by default, and their data is fetched when an app reads them. Seura doesn't see them as in the cloud. A streamed photo opens in the Editor straight away, and an edit creates its edit file as usual. In File Explorer, that edit file later gets Drive's cloud icon, once it's uploaded and the local copy is removed.
- **Deleting a streamed photo from Seura put it in the Recycle Bin,** Nevada found, and it can be restored from there, though the file wasn't on the computer. Rule 5 holds.
- **Claude Code's reading, not yet checked:** Seura recognizes cloud-only files on Windows by the attributes of Windows' Cloud Files system, which OneDrive uses and Google Drive seems not to. The likely cost is that a first scan of a streamed folder downloads every photo for its thumbnails, which the 0.3.1 rule (ask before downloading a selection) can't prevent where Seura can't tell.
- **Nevada broadened #162** from a Mac Delete check to Google Drive and Dropbox on both platforms: scanning, opening, detection, Delete, the deletion notice, and offline. Nevada: they're the three major services, and Drive's different behavior "will merit some documentation". A design session will decide what Seura does where it can't tell.
