# Enhance downloads cloud-only photos (M4 slice 13)

- **The design session's decision, in #195,** then three questions from Claude Code that went back to it: whether a batch can be stopped, what the question's buttons and Esc do, and what the finished message says. It answered: a Stop button with progress, three buttons with Esc as Cancel, and a message always shown when a download was involved. Claude Code had suggested Stop and the message; it had suggested two buttons with Esc as declining, and the design session chose three instead, so Esc does nothing.
- **One undo step, with photos arriving over minutes:** each photo is enhanced as it arrives, so a stopped batch keeps what it did, and the parts add up to one action, recorded when the batch ends. Until then, undo acts on the action before it. Claude Code's choice while building.
- **Choices the decision left open, all Claude Code's:**
  - Photos on the computer are enhanced first, then the downloads run.
  - A second Enhance during a batch waits its turn, as hovering down a row and clicking would, and Stop stops those waiting too.
  - Photos in read-only folders aren't downloaded or counted in the question, since Enhance can't change them.
  - A selection with only one photo in the cloud still shows progress and Stop; one photo alone just shows it on its tile.
- **Found in the real app, on scratch copies marked offline:** after Enhance, such a tile says "In the cloud" in place of its thumbnail. That comes from the test: the mark stays on after reading, where a real download clears it, so Seura asks the system for a thumbnail, and the system has none for a file marked that way. Automation here can't select several photos or slow a download, so the question, progress and Stop are checked by tests only, until Nevada tries them.
- **Nevada tried it on real cloud photos:** Stop feels fast, a batch keeps going in another folder, one Undo undoes the whole batch, and with no connection the Mac says so quickly rather than after the full wait.
- **Nevada caught a message that wasn't true:** stopping a batch of four right away said four photos weren't downloaded, but on the Mac the first one finished anyway, and its cloud badge went away. Seura stops waiting, but its read goes on, on a thread of its own, and a blocked read can't be cancelled. Nevada suggested the message say a download in progress might still complete. Claude Code changed "weren't downloaded" to "weren't enhanced", which holds either way, and added a second sentence only when Stop interrupted one. A photo that arrives this way stays unenhanced. It also qualified the spec's "abandoning a download finishes it on Windows but stops it on the Mac": that was measured by killing a separate process mid-read (`docs/research/cloud-photo-sources.md`), not by a read left running inside Seura. The design session answered in #202 (`2026-11-02-download-stop.md`): it kept "weren't enhanced", gave the second sentence its final wording, "One that was already downloading may still arrive on this computer.", and corrected the spec. It also accepted "may still finish" rather than a real cancel.
- **The order, confirmed:** Nevada agreed that photos on the computer should be enhanced first.
- **Flagged while building, and it was real:** rotate needs no download, so a rotated cloud-only photo gets its thumbnail from the system, which might not show the turn. Nevada confirmed it on real cloud photos and said thumbnails look right after downloading. The fix went in separately (`2026-11-02-cloud-thumbnail-edits.md`).
- **An idea from Nevada, for later:** removing a photo's last edit sends its empty edit file to the Trash, and on the Mac OneDrive often answers with its own "deleted everywhere" dialog. Nevada sees it often enough to propose that Seura warn first, with a checkbox to turn the warning off. Claude Code suggested "Don't show this again", and raised that two dialogs for one undo may be too much, that there's no real choice to offer, and that only OneDrive on the Mac has been seen doing it. The design session chose a one-time message per service instead of a dialog (#202). It's issue #200, for M5 or later. It builds on `2026-10-26-onedrive-trash-notice.md`, which had settled on documenting it.
