# The styled grid (M2 slice 5a)

- **Nevada checked watching (slice 4)** on his PC: deleting files and folders, deleting and restoring them, and renaming them all showed in Seura.
- **He asked what happens to a vanished folder's thumbnails.** They stayed in the cache: thumbnails are named by a hash of path, size, and date, so a restored folder found its old ones again, but a renamed folder's old ones were orphaned for good (about 50 MB per 1,000 photos). Only "Remove from library" cleaned up. Claude suggested a background sweep after the launch scan, deleting thumbnails no photo uses that haven't been touched for about a week, so a quickly restored folder keeps its thumbnails; Nevada added it to slice 6.
- **The grid, from the styled mockup:** square cells with each photo letterboxed, the selection outlined in the accent color, and badges on dark translucent pills for edited photos, ratings, and unreadable edit files. The size slider sets the smallest cell, and cells grow a little so each row fills the width (DSP-3); Claude's first capture showed a wide empty strip on the right.
- **Sorting** (BRW-2) by date taken, file name, or date modified, one order for the whole app, in the core. Names sort as people read them (IMG_9 before IMG_10). The first version of that comparison let letter case decide early, so every "IMG_" came before every "img_"; the test caught it.
- **Selection** (BRW-4) with click, Ctrl or Cmd, Shift, and Select All, and the **ARIA grid keyboard** (ACC-1): arrows, Home and End, Page Up and Down, with the selection following the focus. Screen readers hear each photo's name, date, and rating (ACC-2).
- **Seeing the real app:** Claude now selects a folder in the running app through Windows' UI Automation, without touching the mouse or keyboard, and captures only Seura's window, so slices can be checked against the mockups with Nevada's actual photos.
