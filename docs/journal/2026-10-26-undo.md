# Undo in the Library (M3 slice 5)

- **Built as the design session specified (BRW-11):** Ctrl+Z undoes the last action, whatever is selected now, and Shift+Ctrl+Z (or Ctrl+Y on Windows) redoes it. The app remembers, in memory only, the session's last 10 actions and, for each photo an action touched, the history record it wrote. Undo is the edit format's own undo on each photo, so the record is marked undone, never a new one added, and the Library and the Editor share one history per photo.
- **A photo is left alone** when its latest change isn't that action's record any more, or when its history fails the consistency check. A photo undo leaves alone is dropped from the action, so redo doesn't try it again. The notice says how many were left alone.
- **Emptied files come back, as Nevada decided:** when an action empties an edit file into the Trash, the whole document is kept in memory, and undo writes it back with the record marked undone. Undoing a photo's first change empties its file again, so it goes back to the Trash, and redo brings it back the same way. A file that appeared in the meantime is never replaced.
- **The Edit menu on the Mac** now has Seura's own Undo and Redo, labelled from the history ("Undo Rating (5 photos)", "Undo Add Tag "beach" (3 photos)"). They replace the system's own, which only worked in text fields; when a text field has the focus, the UI passes the command to the field. On the Mac, Cmd+Z goes through the menu, as in every Mac app, so the action happens once. On Windows, which has no menu bar, the UI handles Ctrl+Z itself.
- **One path for writes, still:** undo and redo go through the same step as a change for saving or sending to the Trash, so the rules for emptied files, read-only folders, and files changed on disk are the same. The data-safety suite has a test for undo and redo, including files written back from memory.
