# Metadata in exports (M5 slice 3)

- **No new libraries.** The technical design named `img-parts` to carry the EXIF block and `little_exif` to change it. Claude Code found that `kamadak-exif`, which Seura already uses to read EXIF, has a writer, and that `jpeg-encoder` and `png` can embed the results, so neither library is needed. `kamadak-exif` calls its writer experimental; the version is pinned, and the results were checked in other apps. The technical design's line is corrected to match.
- **The EXIF block is rebuilt, not copied (Claude Code's choice).** Only a list of standard tags goes in, plus the location unless it's removed. That's safer than removing what's known to be a problem, since a vendor's tag can hold anything.
- **Maker notes don't carry over (Claude Code's choice).** They're private vendor data, and some hold preview pictures, which EXP-4 says must never arrive. Nothing can tell which do, so all of them go. The cost is camera details that only the maker's own software reads.
- **More than the plan named had to go.** The Interop block can say "R03", meaning Adobe RGB, which would be wrong for an sRGB file. `SubjectArea` and `SubjectLocation` point at places in the original's pixels, and a crop moves them. Older Windows-written tags such as `XPKeywords` and its rating could contradict the option to include tags and rating, or arrive when it's off.
- **A surprise on Windows: File Explorer doesn't read a PNG's EXIF.** The date, camera and lens were all in the file, and Explorer showed none of them. It does read a PNG's XMP, so Claude Code tried the same facts there, and they appeared. PNG exports now say date, camera and lens in both places. JPEG exports don't need to.
- **The location isn't in that XMP copy (Claude Code's choice).** It stays only in the EXIF, so removing it has one place to work. As a result, Explorer shows no location for a PNG that still holds one, which could make someone think it's gone. Worth a line in the user guide.
- **Metadata too large for a JPEG is an error.** A JPEG segment holds about 64 KB. Rather than quietly lose tags, the export fails, and the same photo fits as a PNG. It would take well over a thousand tags on one photo.
- **A photo with no EXIF gets none invented,** and one with damaged EXIF exports without it, as the rest of Seura treats damaged metadata.
- **How it was checked:** tests make a photo holding a thumbnail, a maker note, its own XMP, an MPF segment and a preview, each marked in its bytes, then search the export's bytes for those marks without a metadata reader. On Windows, the property system File Explorer uses read generated exports' values, and two of Nevada's own iPhone photos for presence only. Those exports were deleted afterward, since they hold GPS.
- **On the Mac,** the Mac session ran the tests, which passed, and exported a generated JPEG and a HEIC made from it with `sips`. ImageIO, which Preview and Get Info use, read the date, camera, lens, keywords and rating, in JPEG and PNG, and the pixels were turned as the orientation tag had said. It reads a PNG's location from the EXIF, and a removed location was gone. Spotlight's importer agreed, except that it gave no lens or rating; it gives no lens for the originals either. `exiftool` isn't installed there, so it wasn't used.
