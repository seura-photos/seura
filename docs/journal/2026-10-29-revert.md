# Revert to original (M4 slice 2b)

- **Revert removes Seura's own operations, as one change in the history,** so undo brings them back (EDT-10). Tags and the rating stay. Other apps' operations stay too: a history record keeps only an operation's `params`, so undo couldn't bring one back whole. That was raised in 2a's pull request, and Nevada merged it without asking for anything else. Operations that are off stay as well: they aren't drawn, and undo would bring them back on.
- **The confirmation puts Cancel where the pointer was** (INT-5). Pressing "Revert to original…" turns that spot into Cancel, with the focus, followed by the question and the destructive choice below. A dialog in the middle of the window would have put its buttons far from the pointer. Esc cancels the revert, not the Editor. Claude Code's choice; the wireframes left the confirmation open.
- **A bug found by checking in the real app, in 2a too.** A change that leaves a photo's file empty sends it to the Trash (FIL-1): a revert, or brightness dragged back to 0 on a photo with no other edits. That change then couldn't be undone, because only the Editor's undo kept the document. EDT-10 requires revert to be undoable. Now every change from the Editor keeps that document while the photo is open, and the next change goes on from it, so the photo's history carries on. The unit tests had used a stand-in Trash that never emptied a file this way. The new test covers revert, brightness back to 0, and the change after.
- **A second slip from 2a:** after an undo, the guard that should have stopped the slider taking a value from another photo compared the photo with itself. It now compares with the photo shown at that moment.
