# Date ranges and the filter row (M4 slice 0b; #125, #118)

- **Date ranges** use `Intl.DateTimeFormat`'s `formatRange` in the region, as the design session answered. Three photos taken in the same minute now read "Mar 26, 2007, 12:51 PM", not the same time twice; a few hours apart, "Mar 26, 2007, 12:51 – 3:05 PM"; in a German region, "26.03.2007, 12:51 – 05.05.2007, 12:51". The catalog's "{ first } to { last }" is gone: the region's own range style replaces it, and it follows ACC-6.
- **The filter row:** the Tags control is a native list, which sizes itself to its longest choice. Its closed text is always "Add a tag…", so a long tag only widened it, without showing. It's now at most 200 px wide, and the open list still shows each tag in full. The row still wraps only when it must.
- **Nevada's check found the row still wrapped** at the default size, with "to" alone on a second line. Measured from a screenshot, the five controls needed about 970 px against about 880 available, and about 900 even with only short tags. So capping Tags at 200 px, the design session's number, couldn't make them fit; it had been an estimate. Claude Code proposed a tighter fit (Tags at 140 px, gaps from 20 to 12 px), which would have just fitted on Windows and maybe not on the Mac.
- **Nevada's suggestion, built instead:** the filter controls are always on two lines, Rating, Tags and Edits, then the dates taken. The area's height no longer changes as the window or the sidebar is resized, and the first line has room to spare. The wireframe now says so, with his decision.
- **Dates checked by Nevada,** with generated photos given dates taken in a small EXIF block: one date for three photos taken in the same minute, and a range within one day written once.
