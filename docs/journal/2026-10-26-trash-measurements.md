# Deleting cloud photos: measurements (M3 slice 9)

The plan's first step for BRW-9: what moving a OneDrive photo to the Recycle Bin or Trash does, with the call Seura uses, measured by Nevada on throwaway copies with a small tool (`crates/seura-library/examples/trash_check.rs`).

- **Found before measuring:** on Windows, the `trash` crate asks the system to warn before deleting permanently (`FOF_WANTNUKEWARNING`). So where a file can't be recycled, such as a USB stick or a network share, Windows itself asks "delete permanently?" instead of deleting silently. Nothing is destroyed without asking, but a Yes would break rule 5, and this already applies to the edit files Seura sends to the Trash. Added to the measurements.
- **Windows, a cloud-only OneDrive photo (Nevada, 2026-10-26):** no dialog. The photo left its folder but did **not** reach the local Recycle Bin. It appeared in OneDrive's recycle bin on the web, which is the only place to get it back. The system call reported success in 150 ms (a 578 KB photo, so it wasn't downloaded first), the same as for a file that does reach the Recycle Bin: Seura can't tell the two apart afterwards, so the confirmation has to say it beforehand.
- **Windows, the same photo downloaded (Nevada, 2026-10-26):** success in 196 ms, no dialog. It went to **both** the local Recycle Bin and OneDrive's recycle bin on the web. Restore from the Recycle Bin put it back in its folder, and OneDrive synced it again; the copy in OneDrive's recycle bin stayed, which is harmless. So on Windows the difference is cloud-only against downloaded: a cloud-only photo can only be got back from OneDrive on the web, and the confirmation should say so when the selection has any.
