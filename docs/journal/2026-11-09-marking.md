# 2026-11-09: Marking for deletion (M6 slice 3)

- **Nevada tested slice 2 on the Mac and Windows** before merging it (#249). Its first CI run stopped with no jobs and "a workflow file issue". No workflow had changed, so Claude Code reran it, and all four jobs passed: a GitHub hiccup.
- **Marks are in `marks.json` in Seura's folder,** never the edit file, as the design session decided (#240). Marking moves nothing, and tests enforce that only that file changes.
- **How a mark follows a photo, Claude Code's choice.** To the index, a rename looks like one photo going and another arriving. Each mark remembers the photo's path, size and modification time. After a scan, a mark whose path has gone moves to the one photo with the same size and time. Fingerprints would be stronger, but they'd read every candidate, and a cloud-only photo can't be read without downloading it (LIB-9). If two photos match, the mark is dropped rather than guessed: losing a mark removes nothing, and the wrong mark could lead to deleting the wrong photo.
- **Marks are settled only after a scan.** With no snapshot, such as after clearing the cache, the index is empty until the first scan ends, and settling earlier would have dropped every mark. A library folder on a drive that isn't connected keeps its marks.
- **The Delete key does nothing in a review, and neither does the Mac's Move to Trash menu item.** The menu goes through `App`, so it needed its own guard.
- **Found by looking at the real screen:** the red outline was dimmed along with the photo, since a CSS filter applies to an element's outline too, and it was hard to see. It's now drawn by filter steps after the dimming. The tests couldn't have shown this.
- **Nevada found that a marked photo in a review looked unmarked on the Mac,** with no dimming and no red edge, though it looked right on Windows and in the Library on both. Review shows the photo on a GPU-drawn canvas, and the dimming was a CSS filter on that canvas; the Library's are ordinary images. Claude Code's reading is that the Mac's web view doesn't apply CSS filters to such a canvas, which it couldn't confirm from Windows. The dimming and the red edge are now a plain layer over the photo, in Review and the Viewer. The Windows checks couldn't have shown this.
- **The button keeps one width,** "Mark to delete" or "Marked ✓", so the actions after it don't move, the lesson of the Cancel button in M5.
- **Decision 0015 lists what Seura's folder holds,** `settings.json`, `Presets/` and `Cache/`, and doesn't have `marks.json` yet. Claude Code left that for a design session, and said so in the pull request.
