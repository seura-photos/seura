- **Nevada ran newly added photos through Review end to end with build 0.5,** across both machines and OneDrive. They copied five photos into a OneDrive folder on Windows. - **Claude Code checked the results, read only:**
  - **Edit files:** all six in the folder pass `check.py`, written by 0.5.0, with each Enhance and rating as its own step in the history.
  - **Originals:** all five photos match the checksum and size their edit files recorded.
  - **Exports:** the four 4-star photos and not the 2-star one, at full size and tagged sRGB, with rating 4 in their XMP. Location is gone, as Nevada's Remove location setting asks, and so are the embedded thumbnail and maker notes. Each export's average brightness is 10 to 19 points (on a scale of 255) above its original, as the Mac's exposure settings say, so Windows rendered the edits that synced over.
- **One finding, #264:** the four enhanced photos' edit files have the photo's checksum but no width and height, while the rated one has both. A new edit file only gets dimensions the index already knows, which it learns when the thumbnail is made, and they were enhanced before that. Later saves fill in dimensions only together with a missing checksum, so these never get them, though the edit format says a writer SHOULD. Read only, Nevada's library has 51 such files. The files are valid and nothing depends on the fields, so it's left for later.
