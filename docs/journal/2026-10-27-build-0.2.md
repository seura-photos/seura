# Build 0.2, and deleting OneDrive photos on the Mac

- **0.2.0 is published** (Nevada's go-ahead, 2026-10-27), as a pre-release, the first public early build (decision 0016). It's tagged at 185dba9 and doesn't have the sidebar, the filter count, or the new messages and notices; those come with 0.2.1. Nevada installed it on both machines. On the Mac, the first launch needed System Settings → Privacy & Security → Open Anyway, as the release notes say. No Terminal command was needed.
- **Nevada's smoke test found one problem (#112):** on the Mac, the installed app couldn't delete a downloaded photo in a OneDrive folder. Nothing was lost: the photo stayed where it was, and Seura said so. It doesn't match slice 9's check, where the app did delete one, but that was a development build started from Terminal.
- **What Nevada measured:**
  - The same installed app, started from Terminal, deletes the photo. So does main's development build from Terminal.
  - The app's OneDrive permission is on (Privacy & Security → Files & Folders), and no app has Full Disk Access.
  - The system log shows the OneDrive permission granted. Then `fileproviderd`, which handles OneDrive's files, refuses: "Dynamic type … was found for item - denying". The reason itself is hidden in the log.

  So it isn't the user's permission. What differs is the app responsible for the request: Terminal, which Apple signs, or Seura, which is only ad-hoc signed.
- **For 0.2,** Nevada and Claude Code agreed to publish with a known issue in the release notes: "on the Mac, photos in OneDrive folders can't be deleted yet; they stay where they are." Next to try, in Claude Code's suggestion on #112: Finder as a fallback, which asks once to let Seura control Finder (slice 9 avoided that on purpose, so it's Nevada's or a design session's choice), and whether Developer ID signing changes it.
