# Decoding colors in full (#188, M5 slice 1)

- **The plan's route didn't hold up.** The plan and #188 said to turn on moxcms's `extended_range`. Claude Code measured it first, as the plan asked, and found two problems:
  - **Wrong values.** Pure green in Adobe RGB came out with an encoded red of −1.94, where the right value is about −0.42. ProPhoto's came out at about −3 billion.
  - **Speed.** About 500 ms per 12 megapixels against 35 ms for moxcms's usual path.
- **What Claude Code did instead:** Seura reads each channel's curve from the profile with moxcms, then applies the matrix to Display P3 itself. Nothing clips, because the matrix runs in linear light. No dependency or feature changed.
  - **Checked against values worked out separately,** from each space's primaries and white point. Adobe RGB's green is (−0.150, 0.954, 0.027) in linear Display P3, and moxcms isn't used to work that out.
  - **Faster than what it replaces:** a whole 12-megapixel conversion takes 105 ms, down from 310 ms, on Windows in a release build, because the curves become a table of 256 values. This measures the conversion alone. The full targets are measured again in slice 9.
- **Still clipped:** a profile built on lookup tables, which moxcms converts. Those are rare for RGB photos.
- **HEIC's `nclx` and PNG's `cICP`, `sRGB`, `gAMA` and `cHRM`** now count, each turned into a profile, so one conversion serves them all.
  - On the Mac, ImageIO already hands over its own profile for HEIC, so `nclx` matters on Windows. No real BT.2020 HEIC was available, so the reading and the conversion are tested separately, not on one file.
  - A PNG's gamma alone, or its chromaticities alone, also count, with sRGB's for the missing part. #188 only named the two together. Claude Code chose this, as the photo's own information.
  - Chunks that make no sense, such as a zero gamma or primaries in a line, are ignored, so a damaged file is taken as sRGB.
- **16-bit PNGs stay at 8 bits, and #188 stays open for that.** The plan allowed it if the cost wasn't small, and it isn't: every decoded photo is `Rgba8` through scaling and conversion. It isn't against the format's SHOULD.
- **The render check's image now holds colors outside Display P3,** so the preview has to treat values below 0 and above 1 as export does. It passed on WebGPU and WebGL2 on Windows.
- **A slip:** Claude Code deleted its temporary example with too broad a command, which took a tracked file with it, and restored that file from git before anything was committed.
