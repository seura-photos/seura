# M6 planning questions (design session)

- **Claude Code raised fifteen questions** planning the Review flow (M6), three where documents disagreed. Claude's answers, mostly Claude Code's suggestions:
  - **Disagreements settled:** the action bar follows the wireframes (ordered for the pointer, INT-5); the summary counts rated, edited, tagged, and marked. One went the other way: the banner keeps the wireframe's "Sort through them one at a time?", because it tells a first-time user what Review is, which "Review them?" next to a Review button doesn't.
  - **Marks** live in Seura's own folder, not the edit file, so they don't create files beside photos or travel to other computers. Claude added that marked photos show in the Library too (dimmed, red outline), so a mark left behind isn't forgotten.
  - **New photos** include those the folder watcher finds while the app runs, not only the launch's scan, since phone photos often sync while Seura is open. Claude Code had suggested the launch only, to avoid stored state.
  - **Cloud-only photos** in a review: asked about once, then downloaded a few ahead rather than all at once.
  - **Restarting a review** starts at the first photo, as suggested, with Home, End and the progress bar to jump.
  - The first-run review offer is dropped.
