# Renamed photos (M3 slice 8)

- **How it works:** when a photo is renamed in Explorer or Finder, its edit file keeps the old name. The scan that follows now reports edit files whose photo isn't there. A photo in the same folder with no edit file of its own and the fingerprint the edit file recorded is the renamed original (edit format, "Reattaching"). The edit file is renamed to match, then saved with the new name in its `file` field. Only an edit file is ever renamed, never a photo.
- **A change from the plan:** the plan had fingerprints computed in the background for every photo on disk. Claude Code computes them only when needed instead, for photos of exactly the size the edit file recorded (a rename doesn't change the size). Fingerprinting a whole library reads every byte of every photo, and in a OneDrive folder that's a lot of disk work for a rename that may never happen. A leftover edit file for a deleted photo then costs at most a few fingerprints, cached afterwards.
- **Unsure matches are left alone.** Two photos with the fingerprint (a renamed photo and a copy of it) or two edit files with it (copies) match nothing, and an edit file is never moved over another. The user's tags stay safe in the old file either way.
- **Not matched:** cloud-only photos (fingerprinting would download them, LIB-9), edit files with no fingerprint (made for a cloud-only photo, until it's read), photos moved to another folder (the format matches within a folder only), and read-only folders.
- **It runs after every scan:** the watcher's, for renames while Seura is open, and the one at startup, for renames while it was closed.
