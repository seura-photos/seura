# A resizable sidebar (M3 slice 11b)

- **Built as the design session specified** (wireframes, "Resizable sidebar"; #74). The divider between the sidebar and the grid can be dragged from 180 to 400 px. Until it's dragged, the default follows the window: 232 px, or 260 px at 1920 wide. The chosen width is kept in the settings as `sidebarWidth`, which is absent until the user drags the divider, and is clamped when read, like the thumbnail size. Double-click resets it.
- **From the keyboard** it's a separator named "Sidebar width", between the sidebar and the grid in the Tab order (ACC-1). ← and → move it 16 px, Home and End go to the narrowest and widest, and Enter resets it. Its value is announced in pixels. Its keys stop there, so the grid's arrow keys don't move the selection at the same time.
- **The grab area overlaps the sidebar's scroll bar** by 3.5 px, since it's centred on the border at the sidebar's edge, as the design gives it. The rest of the scroll bar is still there to grab.
- **Two smaller answers from the same session:** the Filter button shows how many filters are set ("Filter · 2"), one for each chip, so an active filter isn't shown by colour alone (FND-1). And the selected row's bar uses `accentText` instead of `accent`, which is only 2.3:1 against the row's fill in dark mode.
- **Nevada checked it on both machines:** the limits hold, the width is remembered across restarts, and mouse and keyboard both move and reset it. In light and dark on both, the line is visible and highlights on hover and when tabbed to.
