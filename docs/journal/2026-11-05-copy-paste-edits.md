# 2026-11-05: Copy and paste edits

M5 slice 5 (#210; PRE-1, PRE-2). Nevada said to go ahead and stepped away, so Claude Code made the choices below and listed them in the PR for review.

- **The crop rule is in the core, with the edit format's vectors.** A ratio-locked crop keeps its ratio, center and share of the area on a photo of another shape, shrinks until it fits, then moves inward. Keeping the corners out of view already existed in the UI's `crop.ts`, for crop mode; pasting happens in the core, photo by photo, so `seura-edit` now has it too. There are two copies of that arithmetic, and both are tested against the same `crop-inside.json` vectors. Decision 0004's one implementation rule is about rendering, so it doesn't apply, but a third copy would deserve a second thought.
- **A chosen group with nothing copied removes the target's (Claude Code's reading).** The edit format says a preset leaves alone the stages it doesn't contain, "the same rule as pasting edits", but the M5 plan says "pasting that removes the last edit follows FIL-1", which can only happen if an empty group clears. With paste, the user chooses the groups, so PRE-2's "replace" was followed, and the dialog says what will happen beside that group: "None copied, so this photo's will be removed." It's on by default for Adjustments and Effects, as PRE-1 says. This is the choice most worth Nevada's look.
- **A photo with only red-eye counts as having no edits to copy (Claude Code's choice).** Red-eye is never pasted, so there'd be nothing to paste, and the earlier copy would be lost for nothing.
- **A photo on the computer whose size isn't known yet is read for it.** The spec's exception for unknown shapes is about photos in the cloud, which aren't downloaded. A local photo whose thumbnail hasn't been made yet can be read, so it isn't reported as being in the cloud.
- **Paste has only its key on Windows, and the menu on the Mac.** That's what the wireframes draw: Copy edits on the Editor's toolbar, and keys otherwise. It meant the real app couldn't be driven with UI Automation, so Claude Code drove a scratch build through the web view's debug port, with page events rather than OS-level input. That also gave multi-select for the first time, which export's tests had to go without.
- **A mistake caught by the tests:** the Editor's paste hook first went after an early return, which would have changed the order of hooks. The whole Editor test file failed at once, which made it plain.
- **The edit format's submodule moved to include #17,** which says an app replaces only the operations it understands within a stage.
