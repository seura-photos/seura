## Measuring export, and the app-data audit (#225)

- **Export had no way to run without someone choosing a folder,** which #225 noted. Claude Code added a third measuring mode, `SEURA_MEASURE=export`. It saves a preset, applies it to a folder of photos, and exports them all as JPEGs at their own size, timing the export, to the export folder in the run's own settings. `measure.py` runs it on 20 photos of 12 MP, with `--export` to run it alone.
- **The first try on Windows** took 10.3 s, about half a second a photo. That was a release build, but the computer wasn't kept quiet; the full run will give the number to record.
- **The app-data audit gets `--export` too.** It runs that script on a scratch library, with a scratch Seura folder and an export folder in `target/audit`, so Nevada's real library and settings are never touched. It also gets `--release`.
- **The audit passes on Windows:** nothing with Seura's name was written outside the run's own folders. Those held a preset, the cache, the settings, and the three exported JPEGs.
- **Two GPU caches it can't see by name:** Windows keeps a Direct3D shader cache in `AppData\Local\D3DSCache` for each program that uses the GPU, and NVIDIA's driver keeps one in `AppData\Local\NVIDIA\DXCache`. A new `D3DSCache` folder appeared when the release build first ran the export script, and the driver's files changed with it. Seura uses the GPU in its own process for export and for edited thumbnails. Decision 0013 doesn't mention these caches, so Claude Code raised it with Nevada. Nevada chose an issue for a design session (#231): document them, look for a way to minimize them, and see whether the uninstaller can remove Seura's. It doesn't block 0.4.
- **The full measurement:** Nevada left the PC quiet while Claude Code ran it on Windows. Nevada asked the Mac session to do the same on the Mac, with the export audit and a look for Metal's shader cache.

## Results

- **Every target passes on both machines.** The numbers are in `docs/benchmarks/m5-wrap-up.md`.
  - PRF-6's new preset case holds every frame the display shows: 120 a second on Windows and 60 on the Mac, on both preview paths. The core answers a preview in 4 ms at most.
  - Exporting 20 edited 12 MP photos takes 9.4 s on Windows and 7.0 s on the Mac.
- **PRF-5 on Windows is back within the 75 ms aim,** a median of 63 ms against 77 ms in M4. Nothing in M5 set out to change it, and the guide image #190 found is still fetched, so this may be the computer more than the app. #190 stays open.
- **The Mac's export audit is clean too:** nothing of Seura's in `~/Library`, and `~/Seura Photos` unchanged. All 20 exported files are `-rw-r--r--`, which confirms slice 4's fix for exports readable only by their owner.
- **Metal keeps a shader cache for Seura** in the Mac's per-user cache folder, named after Seura's identifier. It's outside `~/Library`, so the audit doesn't see it. It has been there since 2026-10-19 and grew by 32 KB in the run. The Mac session found it; the details are on #231.
- **The core's memory peaked at 679 MB on the Mac while exporting,** against 262 MB browsing 50,000 photos. Exporting holds a whole 12-megapixel photo decoded and rendered at full size, so that's expected; PRF-7 is about browsing.
- **Found while reading the audit:** without `--export`, it quits the app on Windows with `taskkill /IM seura-photos.exe`. That closes every copy of Seura that's running, including one the user has open. The new mode waits for its own process instead.
