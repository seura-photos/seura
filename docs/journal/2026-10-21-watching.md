# Watching for changes (M2 slice 4)

- **Seura notices changes while it runs** (LIB-4): photos added, changed, deleted, or renamed in Explorer or Finder, and edit files changed by another app, show within 5 seconds. It uses the `notify` crate (Windows' change notifications, macOS's FSEvents); the 9.0 line is still in release candidates, so it's 8.2.0.
- **Only what changed is rescanned:** the operating system reports paths, often in bursts (a sync client catching up, a camera import). They're gathered until things are quiet for half a second, or two seconds at most, turned into the outermost folders that changed, and only those are rescanned, with folders above added or pruned as needed.
- **Seura's own cache is ignored**, in case someone chooses a cache inside a library folder; otherwise every thumbnail written would set off another scan.
- **A test that couldn't fail, caught by breaking the code:** the first deletion test still passed with the cleanup of empty folders removed, because Windows also reports the parent folder of a deleted file, so the rescan started higher up anyway. Since that varies by platform, the cleanup is now tested by scanning a single folder directly, and that test fails without it.
