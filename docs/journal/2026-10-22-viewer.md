# The Viewer (M2 slice 7a)

- **Slice 7 split in three**, as slice 6 was, by Claude: 7a the Viewer itself, 7b zoom to 100% and beyond with tiles, panning and wheel and pinch zoom, 7c downloading cloud-only photos when they're opened.
- **The Viewer opens over the Library**, which stays where it was, inert, behind it. So Esc returns to the same scroll position for free, with the last photo shown selected and focused.
- **Photos are drawn by the Editor's preview renderer**, with their edits, as the technical design describes: the core decodes each one to fit the Viewer at the screen's density, in the working space, and the web view uploads it once per photo.
- **Next and previous should feel instant (PRF-5, under 150 ms)**, so the core decodes the two neighbors in the background while a photo is shown, and keeps at most three. Asking for a photo that's still being decoded waits for that decode rather than starting another.
- **Cloud-only photos are never read by the Viewer**, nor decoded ahead: it shows the cloud thumbnail and says the photo isn't on the computer. Downloading on request comes in 7c (LIB-9).
- **Caught in the real app:** Claude's first automated run opened the Viewer, but the arrow keys did nothing. The grid cell that had the focus became inert behind the Viewer, so the keys went nowhere. The Viewer now takes the focus when it opens, as a dialog should for keyboard and screen reader users (ACC-1).
- **Double-click now opens the Viewer for everyone**; M1's Editor moved to `E` in the Viewer, in development builds only.
