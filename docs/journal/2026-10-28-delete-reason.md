# The system's reason when a delete fails (M4 slice 0d; #112)

- **As #112 suggested and the design session agreed:** when the system doesn't move a photo to the Recycle Bin or Trash, the message now gives its own words after Seura's. For example: "1 photo couldn't be moved to the Recycle Bin, so it's where it was. Windows said: Access is denied." On the Mac, it would show the refusal Nevada's log showed only to the system: "you don't have permission to access it".
- **The `trash` crate words its errors for programmers** ("Error during a `trash` operation: Unknown { description: … }"). Seura's Trash module now takes out the system's own sentence: after "`trashItemAtURL` failed:" on the Mac, and after "windows error:" on Windows. The message shows the first photo's reason, since one system call moves them all.
- **When the system reports success but a photo is still there,** no reason is shown. Seura's own placeholder, "the system left it where it was", would have read oddly after "Windows said:".
