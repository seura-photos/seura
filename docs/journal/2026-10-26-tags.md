# Tags and the tag picker (M3 slice 3)

- **TAG-2's matching, built at last.** One function, `tag_key` in `seura-edit`, normalizes a tag (NFC) and applies Unicode's full case folding. Everything that compares tags uses it: de-duplicating in edit files, finding a typed tag's existing form, the picker's filtering, and search. `Ärzte` matches `ärzte`, `STRASSE` matches `straße`, and an é typed composed matches one typed decomposed, as macOS often gives it. Until now, matching only lowercased. Claude Code chose the `caseless` crate (MIT) for the folding, and pinned `unicode-normalization` to 0.1.25 because 0.1.26 was ten days old.
- **A typed tag takes the library's existing form:** typing `Family` when `family` exists adds `family` (TAG-2). It's resolved once, in the core, for the whole selection.
- **The picker follows the wireframe**: title, key hints, chips with ×, a field, then the list. Tags only some of the photos have come first, with "2 of 3" (TAG-8), then the library's other tags with their counts. All the filtering happens in the core, so case folding has one implementation, in Rust, not a second in JavaScript.
- **Raised for the design session: a difference between the wireframe's picture and its notes.** The notes and TAG-3 say "Create tag" shows when the text matches nothing, and Enter adds the highlighted tag. The picture shows "Create tag "fam"" highlighted while "family" matches. Claude Code followed the written requirement: "Create tag" appears whenever the text isn't a tag yet, and the first existing match is highlighted, so typing "fam" and pressing Enter adds "family". To create "fam" instead, move up to it or click it.
- **Where the picker sits:** beside the photo last clicked (or another selected photo on screen) when opened with `T` in the Library, and beside the Info panel's Add tag button otherwise, including in the Viewer, where the photo fills the stage.
- **The Info panel's tags** are chips with × to remove a tag, and Add tag below them. A tag only some of a selection has shows "beach · 3 of 7", and its × removes it from those (TAG-8). In a read-only folder, Add tag stays in place, disabled, the chips have no ×, and `T` shows the read-only notice (TAG-7).
- **The screenshots caught one thing:** with `T`, the picker sat beside the photo first clicked, so with three photos in a row it covered the other two. It now sits beside the last selected photo on screen, in the grid's order, and covers unselected ones instead. Taken as for ratings: Nevada clicking in a development build on the generated test library, and Claude Code capturing the window. The edit files written matched the screen.
- **A test that raced, caught by CI's macos-latest runner:** two picker tests looked for the chips as soon as the picker's field appeared, but the picker loads its choices from the core a moment later. They passed locally and on the other runners by luck. Both now wait for the chips.
