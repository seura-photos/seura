# 2026-11-24: A quit from the Dock or a logout waits for a save (M7 slice 8a, #217)

- **Nevada said to start #217** after #264. Nevada had also set up remote control, so the Mac session can test it.
- **Why the change was lost:** macOS sends a Dock quit, a logout and other quit Apple Events through `applicationShouldTerminate:`. Tauri's windowing library (tao 0.37) doesn't implement it, so AppKit went straight to `applicationWillTerminate:`, too late for the web view to save the Editor's waiting change. #174's fix only covered Seura's own Quit item and the close button.
- **The fix, Claude Code's design:** Seura adds `applicationShouldTerminate:` to the app delegate once the app is ready. The first time, it answers "later" and runs the same save as Quit. When the UI has saved, or after the same 3-second limit, Seura tells AppKit to go ahead. Answering "later" rather than "cancel" means a logout or restart carries on by itself, instead of stopping with a message that Seura interrupted it.
- **No new dependency:** `objc2` 0.6.5 was already in the workspace.
- **Checked on Windows only as far as it can be:** the change is in macOS-only code, which this PC can't compile. The Mac session builds and tests it.
