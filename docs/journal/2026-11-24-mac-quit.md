# 2026-11-24: A quit from the Dock or a logout waits for a save (M7 slice 8a, #217)

- **Nevada said to start #217** after #264. Nevada had also set up remote control, so the Mac session can test it.
- **Why the change was lost:** macOS sends a Dock quit, a logout and other quit Apple Events through `applicationShouldTerminate:`. Tauri's windowing library (tao 0.37) doesn't implement it, so AppKit went straight to `applicationWillTerminate:`, too late for the web view to save the Editor's waiting change. #174's fix only covered Seura's own Quit item and the close button.
- **The fix, Claude Code's design:** Seura adds `applicationShouldTerminate:` to the app delegate once the app is ready. The first time, it answers "later" and runs the same save as Quit. When the UI has saved, or after the same 3-second limit, Seura tells AppKit to go ahead. Answering "later" rather than "cancel" means a logout or restart carries on by itself, instead of stopping with a message that Seura interrupted it.
- **No new dependency:** `objc2` 0.6.5 was already in the workspace.
- **Checked on Windows only as far as it can be:** the change is in macOS-only code, which this PC can't compile. The Mac session builds and tests it.
- **The first build on the Mac failed,** the Mac session found: the workspace denies `unsafe` code, and the new module calls Objective-C. Claude Code had missed that it needs the same local allowance, with a reason, as the other C and Objective-C callers (`measure.rs`, `heif/macos.rs`). Claude Code also pushed the fix once before formatting it, and pushed the formatting separately. The Mac session's old worktree had been removed by macOS's clean-up of `/tmp`, so it made a fresh one, with Nevada's approval.
- **Then it passed on the Mac,** with the Mac session's measurement from #216: an Editor change, then the quit 50 to 62 ms later, on a generated photo with `SEURA_DATA`.
  - The system's quit event (`NSRunningApplication.terminate`): 3 of 3 changes saved, where it had been 0 of 3, with the app gone 127 to 144 ms after the quit.
  - The Quit menu item (Cmd+Q's route) and the close button: 3 of 3 each, as before.
  - With nothing waiting, every route exited within 125 ms, never at the 3-second limit.
  - A second quit 0 or 15 ms after the first, in every order of menu and quit event: each run saved once and exited once, cleanly.
  - The original photo was unchanged after all 24 runs, and the log had nothing but the developer-switch line.
- **A real logout wasn't tested.** It would also close VS Code and the Mac session. The Mac session suggested a logout-style quit event, sent only to the test copy, which would show a cancelled logout as an error, and offered Nevada that or a real logout.
- **Nevada chose the logout-style quit event,** and it passed. The Mac session sent the quit event with the reason loginwindow gives during a logout (`kAEReallyLogOut`) to the test copy alone, and waited for the reply, 52 to 56 ms after an Editor change. All 3 runs replied with success (no -128, so not cancelled) in 84 to 95 ms, saved the change, and exited cleanly. No Automation prompt appeared. It imitates loginwindow's event for one app; a real logout, and whether loginwindow shows its own interruption dialog, remains unseen.
