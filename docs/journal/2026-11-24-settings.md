# 2026-11-24: Settings, first part (M7 slice 3a, #273)

- **Nevada asked for #273 after #293.** Claude Code split it in two, so that each pull request stays reviewable:
  - **3a, this one:** the page itself.
  - **3b, next:** moving and clearing the cache, which needs progress and decision 0018's deletion tests.
- **What's in 3a** (SET-2; wireframes §9):
  - **One page,** in SET-2's order, each change applied at once.
  - **Library folders:** each with its photo count, or Not connected, and Add folder… and Remove, with the Library's own confirmation.
  - **The cache:** where it is and how big.
  - **Seura's folder,** with Open folder.
  - **Export defaults:** the Export dialog's own controls, moved into a component both use. They're saved once changes pause, so dragging the quality slider writes the settings file once, and a custom size waits until it's usable.
  - **Updates:** the checkbox.
- **Windows and the Mac:**
  - On Windows it's a dialog, from ⋯ → Settings… or Ctrl+,, with Close.
  - On the Mac it's a window of its own, from the app menu (Cmd+,), with no buttons. It loads the same page (`index.html#settings`), has a capability that grants only the commands the page uses, and runs incognito like the main window.
  - The page shows its own messages, since on a Mac the main window's messages would be behind it.
- **Left for slice 2:** Updates' "Last checked …" and Check now. Nothing checks for updates yet, so there's nothing to show.
- **A latent bug found on the way:** closing *any* window asked Seura to quit, since the close handler didn't check which window it was. It was harmless with one window, but it would have made closing Settings quit the app. Now only the main window's close quits.
- **Also on the Mac:** while Settings is the front window, the Library's menu commands (Select All, Undo, Delete and the others) do nothing, so Cmd+A or Cmd+Z there doesn't act on photos behind it.
- **The ⋯ menu's order:** Settings…, then About Seura Photos, with About last as is usual on Windows. Clean up… will go between them.
- **Caught before merging: the cache's size counted everything in its folder.** The Welcome screen saves the folder a user picks *as* the cache, not a folder to hold it. So for someone who chose, say, their Desktop, Seura's `thumbs`, `index.bin`, `README.txt` and `WebView` sit beside their own files, and Settings would have shown the whole Desktop's size as the cache. The size now adds up only Seura's own entries, named in one place (`CACHE_ENTRIES`, plus the web view's folder). Claude Code found this while planning 3b, where it matters most: clearing the cache must delete only those entries.
- **Caught before merging: on the Mac, the Settings window was mostly empty.** Nevada saw it looked partly broken and asked for the Mac session to look. It built the branch, Nevada opened Settings, and it found two causes:
  - **The window's permissions were never switched on.** `tauri.conf.json` lists the capabilities by name and named only the main window's, so every command the Settings window called was refused: no folders, no paths, no export options, a disabled checkbox, and the refusal shown as a save failure. CI and the unit tests couldn't see it, since they don't run the Mac window. A new test fails if any capability file isn't listed.
  - **The window's background stopped where the page did.** Its height was 100% of a parent with none, so the bottom of the window showed the darker body colour. It's now the window's height.
  - **Also fixed from its report:** paragraphs in the window now get the same spacing as in the Windows dialog, where it came from rules for dialogs; a failed load says "Settings couldn't be shown" rather than that a setting couldn't be saved; and the window now uses the system's region for sizes and follows pseudo-translation, as the main window does (ACC-6, ACC-7).
- **And one spacing slip, on both systems:** the Mac session's recheck found the notes and paths had lost their space below, so "Your settings and presets, in a folder you can see." sat 2 px above Open folder. The dialogs' paragraph rule (no margin) outranked the settings page's own. The page's rules now come first, in the Windows dialog and the Mac window alike.
