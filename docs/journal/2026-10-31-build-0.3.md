# Build 0.3 (M4 slice 11)

- **Version 0.3.0, with the Editor:** the first public build with editing. It holds every M4 slice from 1a to 11 (#151 to #191), and the button states (#184).
- **M1's development-only export isn't in it,** as Nevada decided in slice 11, so edits show in Seura but can't be taken out of it until M5. The release notes say so.
- **Known issues named in the notes:**
  - an edit in the last second before quitting isn't saved (#174);
  - wide-gamut colors are clipped when decoding (#188);
  - photos in OneDrive and similar folders can't be deleted on the Mac (#112).
  - #190, PRF-5 on Windows, is left out: it's within the target, and testers won't notice it.
- **The release workflow's comment** no longer says the Editor isn't in release builds.
- **Before tagging, Nevada found a focus slip:** after clicking Enhance in the Library, Enter didn't open the selected photo; you had to click back in the grid first.
  - The click moved the focus to the button. Enter then pressed Enhance again, which changes nothing the second time.
  - The quick fixes in the toolbar and on a hovered photo had the same slip. With focus on a hovered photo's button, Enter would both press it and open the photo.
  - Claude Code suggested that a click on a quick fix leave the focus where it was, as in many apps' toolbars, with Tab still reaching the buttons. Nevada chose to fix it before tagging 0.3.
  - On the Mac, Enter at first didn't open a photo at all. Nevada then found the Mac was on main, without the fix; on the fix branch, Enter and the arrow keys worked there too. If Enter fails again after a plain click on a photo, it's a separate bug.
- **Nevada published 0.3.0** from the draft pre-release that the tag made, after reading the notes Claude Code wrote. Nevada now uses the release builds.
- **Devlog part 10, "Fix":** Claude Code drafted it (website PR #7); Nevada made a change and published it.
  - Its two screenshots are of the installed 0.3 on a scratch library of copies of Nevada's Flowers test photos, checked for location data first, with a scratch `SEURA_DATA` so the real library wasn't touched.
  - While drafting, Claude Code found the website's copy of the edit format's schema was out of date, so a file with highlights or shadows didn't validate against it. Website PR #6 copied the current schemas from the edit-format repository.
  - The home page's "Try an early build" still said editing was coming. Nevada gave that to the design session, which updated it (website PR #8).
