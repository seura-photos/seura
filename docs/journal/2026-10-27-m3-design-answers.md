# M3 wrap-up: design answers (design session)

- **Claude Code brought fourteen questions** from building M3, in four groups: what's needed to finish (when to build 0.2, the resizable sidebar, early builds on the website), deleting photos, notices, and its own choices to confirm. Nevada agreed with all of Claude's recommendations, and said how he'd like to work from here: he'll generally defer to Claude on current practice, and ask for changes after seeing the running app. "Trust, then verify."
- **Build 0.2 now,** without the resizable sidebar, so tagging his own library can start; the sidebar follows in 0.2.1, still in M3.
- **Early builds go public from 0.2** (decision 0016): a "Try an early build" section on the website, and new release-note wording.
- **Cloud-only photos stay out of Delete.** Deleting them anyway, as Finder does with a warning, would send a photo off every device, recoverable only from the service online, and on Windows silently. Opening a photo downloads it, so anything the user has looked at can be deleted normally; downloading the rest first is planned with Review in M6. Drives with no Recycle Bin are treated the same way.
- **Messages moved.** Nevada had found the last action's notices easy to miss under FOLDERS. Claude separated two kinds: problems with the selected photos' files stay in the notice bar at the top; the last action's result becomes a brief message near the bottom of the photo area, in the Library and Viewer alike (INT-6). The status bar was rejected as the easiest place on screen to miss.
- **Contrast fixes found by Claude while checking:** the selected row's new accent bar was only 2.3:1 in dark mode, so it uses accentText; empty stars become outlines in a darker gray (3.8:1 and 4.0:1), and disabled stars keep the old faint gray as a token of their own.
- **The tag picker:** Claude Code's behavior (Enter takes the first match) stands, and the wireframe's picture, which showed Create highlighted, was corrected.
