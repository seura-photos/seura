# Reference images for the edit format (M4 slice 10)

- **The appendix's last pieces** went to edit-format #15. "The whole pipeline" gives the order a pixel goes through in one pass. Reference images check whole renders, not one formula at a time: a 64 × 48 photo and seven cases, rendered in double precision by a new `tools/reference.py` from the appendix's own formulas. They check the luminance guide whole, which the luminance-guide file had promised for 1.0. The photo is under 1024 pixels, so the guide is built on it directly and the downscaling filter, which the format leaves open, plays no part.
- **Seura's GPU render matched all seven on the first run,** within one 8-bit level. The Python is new and doesn't share code with the shaders, so this is the first check of a whole Seura render against the format's text rather than against Seura's own definitions. The test (`the_shaders_match_the_reference_images`) waits for #15 to merge and the submodule to move.
- **Questions for 1.0, raised with the design session in #15:** how a photo is decoded into the working space isn't specified (profiles, bit depth, HDR gain maps), so two apps can draw one edit file differently; the guide's downscaling filter is "any good filter"; and the main spec's "Color" paragraph should point to the appendix.
- **The design session reviewed the whole appendix and approved #15,** and answered the three questions in edit-format #16. A decoding paragraph (SHOULD): honor the photo's own color information, convert unclipped in floating point, and render an HDR photo's SDR image. Any guide downscaling filter that averages every source pixel a guide pixel covers, which Seura's Lanczos and area average both do. The Color paragraph now points to the appendix. It also noted that the 64 × 48 reference photo exercises the guide only at radius 1, so the planned sample-photo conformance tests should include a photo over 1024 pixels.
- **Seura doesn't fully meet the decoding paragraph** (#188), found by Claude Code checking it. Colors outside Display P3 are clipped while decoding: an Adobe RGB pure green loses its negative red. HEIC color descriptions other than Display P3 fall back to sRGB, PNG color chunks other than an ICC profile are ignored, and 16-bit PNGs are reduced to 8 bits.
