# Start over (M3 slice 7a)

- **Slice 7 is in two parts,** as slice 6 was: Start over (FIL-4) first, since it's a new write path and needs the data-safety tests, then the notices for unknown content (FIL-5) and changed originals (FIL-7), which have no API yet.
- **FIL-3 is mostly done already.** The watcher re-reads an edit file changed on disk and the grid follows, and a Library write that meets a file changed since it was read leaves it alone. The rest of FIL-3 ("Keep yours or load theirs?") applies only while a photo is open in the Editor, which ships in M4 and is still development-only. Claude Code suggests moving that part to M4, for Nevada to decide.
- **Start over** moves the unreadable file, unchanged, to `Unreadable edit files` in Seura's folder, named `2026-10-26 143012 IMG_1234.jpg.seura.json`. A second one in the same second gets `(2)` after the time, never the same name. Where a move isn't possible (another drive), the file is copied, then the original goes to the Trash. If the Trash refuses, the copy Seura just made is deleted (rule 5's exception) and the original stays.
- **Before moving anything,** Start over reads the file once more. If it can be read now (fixed, or synced again since), it's left alone and read again. In a read-only folder it does nothing, as tagging doesn't (TAG-7).
- **The time in the name is the user's own clock.** The `time` crate can't find the local time zone safely in a multi-threaded app on the Mac, so the UI sends its offset with the request.
- **The notice bar** sits at the top of the main area, above the heading, when the selection includes a photo whose edit file can't be read. It explains and offers Start over, and that click is the confirmation (FIL-4), with no dialog (flow 11). Afterwards it says where the file went, with Show in folder, which can only show files in that one folder.
- **The app-data audit** only launches and quits the app, so it doesn't exercise Start over. The destination is fixed in code to Seura's folder, and the data-safety suite checks that the file arrives there unchanged and that nothing else in the library changes.
- **A lint error was caught before pushing** this time, by running every check after the last change (the rule from slice 6a).
